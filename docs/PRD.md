# PRD：产品团队模式（virtual-product-team）v1.0.0

> 状态：草稿待老板审核（第 3 步交付物）
> 日期：2026-08-16
> 依据：产品定义（第 2 步交付物，老板已拍板三个决定）

## 1. 背景与目标

**背景**：非技术个人开发者有想法，但无法独立完成"想法→产品→发布"。现有工具要么闭源不可定制（WorkBuddy、Trae SOLO、Coze 3.0、Lovable），要么需要写代码（MetaGPT、CrewAI、OpenHands），要么只覆盖部分环节（多数止步于部署预览）。"老板式对话 + 虚拟团队 + 覆盖发布/宣传 + 可自托管"的组合无人占据。

**目标**：为 DeepSeek Harness（DSH）新增「产品团队模式」agent preset——用户开一个对话说"我有个想法"，AI 就以虚拟产品团队身份，带他走完 12 环节流水线（归纳为 6 个阶段技能），用户全程只说话、只拍板，无需懂任何技术。

**成功标准（自举验收）**：用「产品团队模式」开发出「产品团队模式」本身，走完整条流程并发布到 GitHub（v1.0.0）。

## 2. 目标用户

- 非技术背景的个人开发者（无编程/团队经验，自学摸索）
- 使用 DSH Web 界面（`dsh web`）
- 有想法、想自己做产品、不想学编程

## 3. 功能需求（每条带验收标准）

### FR-1 模式注册
安装后，新建对话时可选择「产品团队模式」预设。
- 验收：目录 `~/.dsh/.agent-presets/virtual-product-team/` 放置后，新建会话的预设选择器中可见「产品团队模式」。

### FR-2 老板式启动
用户直接说"我有个想法……"或描述想法，AI 自动进入流水线第 1 阶段，用户无需说任何技术词汇（skill / agent / preset / 插件等均不必提）。
- 验收：persona 明确声明"用户是非技术老板，不要求也不期待他说技术词；所有流程引导由 AI 主动完成"。

### FR-3 阶段门禁（Stage-Gate）
每个阶段结束，AI 必须产出该阶段的文档/清单，向老板汇报并请求确认；老板点头才进入下一阶段。
- 验收：persona + 各阶段 skill 明文规定"每阶段以确认收口（ask_user_question 或文字请求确认），未获确认不得推进"。

### FR-4 六阶段技能（每个 SKILL.md 独立、可加载）
| 编号 | 技能 | 覆盖环节 | 产出物 |
|---|---|---|---|
| 01-vision | 愿景 | 想法验证 + 产品定义 | 问题陈述/目标用户/竞品/产品定义（MVP 范围+成功标准） |
| 02-requirements | 需求 | 需求设计 | PRD（背景/目标/用户故事/功能与非功能需求/验收标准/非目标） |
| 03-design | 设计 | 技术设计 + 任务拆分 | 技术设计文档、任务清单（每任务带验收标准） |
| 04-development | 开发 | 开发实现 | 源代码、单元测试、todo 跟踪、Conventional Commits |
| 05-qa | QA 与审计 | 质量测试 + 安全审计 | 测试报告、功能对照验收、安全清单（密钥/依赖/OWASP/个人路径） |
| 06-release | 发布 | 发布准备 + 部署 + 宣传材料 | README 中英、CHANGELOG、LICENSE、install.sh/uninstall.sh、semver、tag |

- 验收：每个 SKILL.md 位于 preset 的 `skills/<编号>-<名>/SKILL.md`，可被模型按需加载并指导对应阶段执行。

### FR-5 自举验收
用「产品团队模式」开发出「产品团队模式」本身并发布到 GitHub。
- 验收：全流程跑通，产出可分发仓库 v1.0.0（含 README/CHANGELOG/install.sh）。

### FR-6 可安装、可卸载、可回滚
- 验收：install.sh 一键安装到 `~/.dsh/.agent-presets/`；uninstall.sh 移除；卸载后标准/创造模式不受影响、原样恢复。

## 4. 非功能需求

- **NFR-1 兼容性**：DSH 0.1.0-rc 阶段；只使用用户级目录 `~/.dsh/.agent-presets/`（升级不覆盖）；不改 DSH 出厂安装。
- **NFR-2 安全**：不收集用户数据；不执行未授权命令；密钥绝不进文档；模型输出不落盘敏感信息。
- **NFR-3 分发纪律**：零个人路径、零密钥、零开发流水账；对外只用语义化版本号；author=songoao25。
- **NFR-4 可回滚**：卸载后系统完全恢复原状，不残留。

## 5. 非目标（第一版不做）

- 团队进度面板 UI（第二版）
- 多语言本地化（对外文档仅中英）
- npm 包分发（先走 GitHub 仓库 + install.sh）
- 运营/迭代环节的自动化（第 11、12 环节留给用户用后续版本）
- 与 WorkBuddy / Trae 等外部平台集成

## 6. 成功指标

- **主指标**：自举验收通过——用产品团队模式开发出它自己并发布 GitHub v1.0.0。
- **副指标**：对比实验——同一想法分别用普通模式与产品团队模式跑，产品团队模式产出完整可发布仓库，普通模式不能。

## 7. 依赖

- DSH agent preset 机制（`agent.cordis.yml` / `preset.yml` / `skills/<名>/SKILL.md`）
- 子代理与工作流工具（tool-subagent / tool-workflow），用于开发/审计阶段扇出子 Agent
- 用户已有 bottom-info-bar 的分发经验（install.sh / README 中英 / CHANGELOG 模式可复用）
