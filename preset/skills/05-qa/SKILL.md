# 阶段 5：QA 与安全审计

## 角色
你是 QA 工程师 + 安全审计员。任务：证明"功能都做完了、能安全分发"，或明确列出没做完/不安全的地方。

## 目标
产出 `docs/AUDIT.md`（功能验收表 + 安全检查表），全部通过或明确列出遗留问题。

## 步骤

1. **功能验收**：对照 `docs/PRD.md` 的每条功能需求（FR-x）逐条检查实现：
   - 实现了吗？（跑一遍/看代码/看测试）
   - 满足验收标准吗？
   - 结果记入验收表：`✅ 通过 / ⚠️ 部分 / ❌ 未通过`
2. **跑测试**：执行项目测试，记录结果。
3. **安全清单**（逐项检查）：
   - [ ] 无硬编码密钥/Token（扫描代码中的 `api_key`/`token`/`secret`/`password` 等字样与真实密钥模式）
   - [ ] 无个人路径泄露（扫描本机用户目录路径字样：macOS 的「斜杠 Users 斜杠」前缀、Windows 的「C 冒号反斜杠 Users 反斜杠」前缀——分发内容必须零个人路径）
   - [ ] 依赖漏洞：如有 lockfile，检查是否存在已知高危 CVE（可用 `npm audit` 等工具）
   - [ ] OWASP 重点项：注入、敏感数据暴露、越权（按产品类型判断适用项）
   - [ ] 默认配置安全：无危险默认值
4. **写审计报告**（`docs/AUDIT.md`），模板：

```markdown
# 审计报告：<产品名>

## 功能验收
| 需求 | 结果 | 说明 |
|---|---|---|
| FR-1 ... | ✅/⚠️/❌ | ... |

## 测试结果
<测试命令与结果>

## 安全检查
- [x] 无硬编码密钥
- [x] 无个人路径
- [ ] ...（未过的项写明）

## 遗留问题
| 问题 | 严重度 | 处理建议 |
|---|---|---|
| ... | 高/中/低 | ... |

## 结论
<是否达到可分发状态；未达到则列出必须修复项>
```

5. **汇报 + 请求确认**：向老板汇报"审计完成：功能 N 条通过 / M 条有问题；安全检查 X 项通过 / Y 项有问题；结论：可以发布 / 需要先修……"。**老板点头才进阶段 6**；若有必须修复项，先修复再复验。

## 验收标准
- [ ] 功能验收覆盖 PRD 全部需求
- [ ] 安全检查完成；无硬编码密钥、无个人路径
- [ ] 审计报告留档；结论明确
- [ ] 达到可分发状态（或明确列出待修复项并已修复复验）
