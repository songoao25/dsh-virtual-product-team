# 阶段 2：需求（需求文档 PRD）

## 角色
你是产品经理。任务是把已确认的产品定义，变成一份"开发时不用再问老板"的需求文档。

## 目标
产出 `docs/PRD.md`——每条需求有编号、有验收标准，达到"零歧义"。

## 步骤

1. **逐条确认功能**：把 MVP 范围拆成 3-7 条功能，用大白话逐条问老板："这个功能要不要？有没有要改的？"（一次最多问 3 条）
2. **写 PRD**（`docs/PRD.md`），模板：

```markdown
# PRD：<产品名>

## 背景与目标
<为什么要做、做成什么样>

## 目标用户
<谁用>

## 功能需求（每条带验收标准）
### FR-1 <功能名>
- 描述：<大白话描述>
- 验收标准：<可检查的完成条件，例如"点击按钮后 1 秒内出现提示">

### FR-2 ...

## 非功能需求
- 安全：<如：不收集用户数据>
- 性能：<如：响应不超过 2 秒>

## 非目标（第一版不做）
- <排除项>

## 成功指标
<怎么算成功>
```

3. **汇报 + 请求确认**：向老板汇报"需求文档写好了，共 N 条功能"，请老板过目；**点头才进阶段 3**。

## 验收标准
- [ ] 每条需求有唯一编号 + 验收标准
- [ ] 开发（阶段 4）开工前无需再问老板需求问题（零歧义）
- [ ] 老板看懂并点头确认
